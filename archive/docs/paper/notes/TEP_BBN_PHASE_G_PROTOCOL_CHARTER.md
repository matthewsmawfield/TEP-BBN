# Phase G: TEP-BBN Protocol Charter

This charter defines the immutable, preregistered execution protocol for Phase G (the blinded multi-system TEP prediction test). It governs how the predictive test will be administered and evaluated, guaranteeing separation between derivation, unblinding, and prospective evidence.

*Note: The exact physical TEP prediction rule is developed separately and will be frozen in a sealed `TEP_BBN_PHASE_G_PREDICTION_CONTRACT.md` before this protocol may be executed.*

## 1. Sample Roles

Systems are strictly assigned to one of three categories before execution:

* **Development:** Systems already inspected in detail (e.g., Q1009). These are strictly quarantined and may only be used to derive the TEP prediction rule. They cannot contribute to prospective discovery evidence.
* **Locked Retrospective Validation:** Systems not used to alter the sealed rule after contract freeze, but which were historically unblinded or otherwise not pristine. Used for supportive robustness testing only.
* **Untouched Confirmation:** Systems whose candidate D-windows and velocities remain strictly concealed until predictions are stored and hashed. The primary TEP-specific discovery claim rests solely on this cohort.

## 2. Permitted and Prohibited Inputs

### Permitted Non-D Inputs
The TEP rule is permitted to process only the following observables:
* Main H I parent and interloper velocity components (derived securely from non-D windows).
* Associated metal components and column densities.
* Established redshift parameters and documented instrumental configurations.
* High-order Lyman series limits where masking rules strictly exclude the candidate D-window.

### Prohibited Inputs (Data Leakage)
Before a system is formally unblinded, the prediction code must be mathematically and programmatically isolated from:
* Candidate D-window flux and corresponding error arrays.
* Spectral residuals derived from candidate pixels.
* Continuum solutions explicitly fitted over or using the candidate pixels.
* Component architectures manually tweaked after inspecting candidate pixels.
* Any prior human metadata, notes, or proxies disclosing the candidate's velocity offset.

## 3. Common Spectral Pipeline & Model Family

The evaluation relies on the fully validated, frozen astronomical infrastructure:
* **Infrastructure:** Physical Voigt engine, deterministic transition routing, unique-pixel masks, Student-(t) likelihood, continuum handling, and identical nuisance configurations across systems.
* **Model Family:** Every system evaluates four constrained structures:
  1. $M_{\rm NULL}$
  2. $M_{\rm D}$ (Standard deuterium interpretation)
  3. $M_{\rm H,free}$ (Unrestricted generic H interloper)
  4. $M_{\rm TEP}$ (Kinematic interloper strictly bounded by the sealed TEP prediction contract)

## 4. Comparison Statistic & Decision Thresholds

Because $M_{\rm TEP}$ is a restricted subset of $M_{\rm H,free}$, raw maximum likelihood is mathematically guaranteed to favor $M_{\rm H,free}$. The evaluation relies instead on **predictive concentration**.

### Primary Comparison Statistic
The evidence must be evaluated via simulation-calibrated predictive scoring, marginal likelihood, or the prequential score:

$$ S_i = \log \frac{ \int L_i(v,j) \pi_{\rm TEP}(v,j\mid x_{i,\rm nonD})dv\,dj }{ \int L_i(v,j) \pi_{\rm H,free}(v,j)dv\,dj } $$

where $\pi_{\rm TEP}$ is the prior generated by the sealed prediction contract, and $\pi_{\rm H,free}$ is the broad kinematic alternative.

### Discovery Threshold
Strong TEP evidence requires the protocol to meet the following threshold:
1. TEP selects the correct component and displacement sign before unblinding.
2. The concentrated TEP prediction repeatedly encompasses the true solution better than the unrestricted generic $M_{\rm H,free}$ alternative.
3. Predeclared null-systems explicitly evaluate as negative controls.
4. At least one untouched confirmation system yields success, replicated by independent subsequent observations.

## 5. Blinding and Unblinding Procedure

To enforce rigorous blinding, a machine-readable manifest must be constructed for each confirmation system prior to any inference.

1. **Manifest Freeze:** Freeze and hash candidate-window bounds, masked-pixel files, allowed-feature metadata, and metal-component catalogues.
2. **Prediction Storage:** Run the TEP Prediction Contract to generate `(j, sign, p(\Delta v), p_{\rm null})`. Hash the exact JSON prediction output and its timestamp.
3. **Execution & Unblinding:** The pipeline unblinds the candidate window by combining the input state and the stored prediction. The unblinding timestamp is recorded. Predictions cannot be overwritten post-unblinding without instantly voiding the system's confirmation status.

## 6. Stopping Rules & Final Deliverables

The protocol completes by yielding one of the following decisions for each system/aggregate run:

* `TEP_PREDICTIVE_SUPPORT`
* `FREE_H_STRUCTURE_WITHOUT_TEP_IDENTIFICATION`
* `CONVENTIONAL_D_SUPPORTED`
* `PREDICTIONS_INCONCLUSIVE`
* `TEP_PREDICTION_RULE_NOT_DERIVED`
* `ABSORBER_MODEL_INADEQUATE`

Upon completion of the designated sample, evaluation is paused. The sample may only be expanded according to formally predeclared extension rules.
